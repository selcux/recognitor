# Recognitor Open Questions & Tradeoffs

This document tracks architectural decisions, resolved choices, and design tradeoffs.

---

## 1. Resolved Decision: Database Layer (CozoDB)

### Decision: CozoDB over SQLite and SurrealDB
- **Why SurrealDB was rejected:** SurrealDB does not support cross-namespace graph edges (re-creating Basic Memory's project silos), lacks built-in graph algorithms like PageRank, and introduces massive binary and compile-time bloat from its distributed server architecture.
- **Why CozoDB won over bare SQLite:** While SQLite is battle-tested, implementing recursive graph traversals, PageRank, and vector search in SQLite requires assembling and maintaining separate extensions (`sqlite-vec`, custom recursive CTEs, and external graph libraries like `petgraph`). CozoDB integrates relational tables, Datalog recursive rules, built-in PageRank, and HNSW vector search in a single pure Rust embedded crate.

## 2. Edge Notation Syntax in Markdown Notes (Open)

How should typed edges be authored by humans and generated by LLMs inside Markdown files?

### Option A: Frontmatter Edge Mapping
```yaml
---
title: Auth Flow
namespace: backend
relations:
  - predicate: implements
    target: "Security Spec"
  - predicate: depends_on
    target: "User DB Schema"
---
```
- **Pros:** 100% deterministic parsing via standard YAML parsers; zero regular expression parsing over the note body; clear separation of metadata from prose.
- **Cons:** Edges are detached from inline text; humans editing notes must jump to the top of the file to add a relation.

### Option B: Dataview Inline Semantic Fields
```markdown
# Auth Flow

This module implements:: [[Security Spec]] and depends_on:: [[User DB Schema]].
```
- **Pros:** Inline context is preserved; natural for humans writing in Obsidian; matches the Dataview community convention.
- **Cons:** Requires custom regex or Markdown AST token scanning; higher potential for LLMs to generate malformed inline keys.

### Option C: Dedicated Markdown Section (Basic Memory Style)
```markdown
## Relations
- implements [[Security Spec]]
- depends_on [[User DB Schema]]
```
- **Pros:** Human-friendly; LLMs generate lists reliably; easy to read in plain text.
- **Cons:** Requires reserving a specific heading name; parsing breaks if the heading is translated, renamed, or formatted differently.

## 3. Invalidation & Sync Architecture (Open)

How does the CozoDB index stay in sync with local Markdown files?

1. **Filesystem Watcher (Notify crate in Rust):**
   - Continuously monitors the directory tree in the background while the MCP server runs.
   - Updates changed files incrementally in near real-time.
2. **On-Demand Stale Check:**
   - Checks file modification times (`mtime`) and checksums at query time or tool invocation.
   - Avoids running a continuous background watcher thread.
3. **Explicit Sync / Rebuild:**
   - Requires explicit CLI or tool triggers (`recognitor sync` / `recognitor rebuild`).

## 4. Cross-Domain Agent Scoping & Privacy (Open)

When an agent is queried within a specific domain, how should cross-namespace edges be exposed?

1. **Strictly Permissive Traversal:**
   - The initial query filters on the active namespace, but any hop across an edge to another namespace is followed automatically.
2. **Explicit Hop Permissions:**
   - Agent config dictates whether cross-namespace traversal is allowed (e.g. `allow_cross_domain: true` or `allowed_domains: ["work", "public"]`).
3. **Depth-Decayed Weighting:**
   - Edges crossing a namespace boundary incur a weight penalty or depth reduction so agents only see immediate boundary notes.

## 5. Graph Fan-Out & Traversal Strategy (Resolved in Principle)

Instead of hard depth truncation (e.g. blind BFS cutoff at depth 2), Recognitor will leverage CozoDB's built-in graph algorithms and Datalog rules:
- **Personalized PageRank / Topic Walk:** Biases the walk toward seed nodes matching the prompt, pruning off-topic branches mathematically regardless of depth.
- **Hub Dampening:** High-degree hub nodes have their edge weights dampened by inverse degree to prevent generic index pages from overwhelming specific thematic threads.
